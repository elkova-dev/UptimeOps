# Как вести личный GitHub-репозиторий

1. Заведи отдельный GitHub-репозиторий `uptimeops`.
2. Перед первым push проверь работу на своём компьютере, `pytest -q` и не загружай папку `data/`.
3. Добавь README с честной формулировкой **local prototype**, а не `production-ready SaaS`.
4. Начальный коммит отражает то, что реально уже создано; следующие коммиты соответствуют новым реальным изменениям.
5. Публикуй issues, скриншоты, тесты, документацию, CI и архитектурные решения.
6. Отдельно объясняй, что код сначала был подготовлен с ИИ, но ты проверил и разобрал архитектуру. На собеседовании будь готов менять код самостоятельно.
